# 共通作業ルール(全マシン・全リポジトリ)

> 正本 = `src/setting/claude/CLAUDE.md`(git 同期)。各マシンへは `setting/install.sh` で配置する。
> **このファイルを直接編集しない。** 配置先(`src/CLAUDE.md` 等)はコピーなので、直すのは正本のほうです。
> 案件固有のルールは各リポジトリ/WS 配下の `CLAUDE.md` に書き、こちらには置かない。

## 1. 考察・製作は「フレッシュなエージェント」に並行で任せる(既定)

**2026-09-22 ルール化。** 専用のスラッシュコマンドは存在しないので、この文書が規定です。

### 適用する作業
- 分析・考察(構造化、原因の切り分け、対比、影響範囲の見積り)
- 製作(資料・原稿・提案・設計案・マップの作成)
- 複数の観点から同じ素材を読み直す作業

これらは既定で **`Agent` ツールの新規エージェント**に、観点ごとに**並行で**担当させます。

### なぜか
セッションの文脈には、**既に崩れた前提や途中で訂正した数字が残っています**。それを引き継いだまま考察すると、誤った前提が結論まで運ばれます。**白紙から素材を読み直させるほうが誤りが伝播しません。**

⚠️ `subagent_type: "fork"` は**使わない**。fork は親の文脈をそのまま継ぐため、この目的を満たしません。

### 適用しない作業(そのまま自分でやる)
- 単一の事実の参照(ファイルが在るか、値が何か)
- 既に読んだファイルの小さな編集、機械的な置換
- **ユーザーとの対話・合意形成・グリル**(分割できない)

### 並行数
独立した観点ごとに 1 体、**3〜5 体まで**。観点が重なるなら分けない(同じ素材を 2 体に読ませない)。

### エージェントに必ず渡す 5 点
1. **絶対パス**
2. **機密かどうか**と、出力先のローカルファイル指定(外部送信させない)
3. **その環境の罠**(下記 §3)
4. **要約禁止** — 原文をそのまま持ち帰らせる。要約のたびに制約の意味が変わります
5. 実測値のみを報告させ、推測には「推測」と明記させる

### 受け取る側の責任
エージェントの結論を**そのまま信じない**。とくに件数は、別の手段で 1 つでも手検算して突き合わせてから採用します。

## 2. 報告の型
- **結論 → 詳細**の順で短く。長い説明は読まれません。
- **日本語**で書く。
- 作業過程は、結論の信頼性に効くときだけ書く。
- 件数・日付・金額は**実測値のみ**。推測は「推測」と明記する。
- 失敗・未了は隠さずそのまま書く。

## 3. 環境の罠(OS 別)

### Windows
| 罠 | 対処 |
|---|---|
| cp932 で `—` や絵文字を print すると Python CLI が落ちる | 冒頭で `sys.stdout.reconfigure(encoding="utf-8")` |
| Git Bash の `grep` は日本語ロケールで絵文字をまたげない(行が在るのに 0 件) | 表を引くときは `LC_ALL=C` |
| PowerShell は**変数名の大小を区別しない**(`$R` と `$r` が同一) | 変数名を明確に分ける |
| PowerShell の `Select-Object -First` は native の終了コードを壊す | ログに全部落として `-Last` で見る |
| zip 内のファイル名に `:` が入ると、展開時に NTFS 代替データストリームになり**中身が消える** | `:*?"<>\|` を `_` へ置換してから展開 |
| Google Drive for desktop は同期中のファイルを掴む(`WinError 5`) | 再試行＋保存間隔を空ける |

### macOS
| 罠 | 対処 |
|---|---|
| cron は **bash 3.2** で走る。`set -u` + 空配列展開が cron でだけ即死し、手動実行では再現しない | 配列は `${A[@]+"${A[@]}"}` 形式で |

### 共通(ファイル読み取り)
| 罠 | 対処 |
|---|---|
| `openpyxl` が入っていない Python 環境がある | zip + XML 直読で済ませる |
| xlsx の空セルは `<c r="B13" s="29"/>` と自己終了で書かれ、素朴な正規表現だと**次のセルを飲み込んで列がズレる** | 自己終了を先に、非貪欲で切り出す |
| xlsx のセル属性の並び順はファイルごとに違う(`t="s"` が `r=` より前に来る) | 属性全体から `t=` を探す |
| xlsx の sharedStrings に `<rPh>`(ふりがな)が混ざる | 除去してから本文を取る |
| PDF は文字抽出に見せかけて壊れることがある。康熙部首の別コードポイント(`⾕` `⼯` 等)が混ざり、素の grep が 0 件になる | `unicodedata.normalize("NFKC", …)` で正規化。2〜3 本は必ず目視確認 |

## 4. git の作法
- **コミットはパス限定で打つ**: `git commit -m "..." -- <dir>`。並行セッションの `git add` が混入します。`add` だけでは足りません。
- 作業スクリプトの冒頭で `git branch --show-current` を確認する。「ファイルが無い」はブランチ違いを疑う。
- `git checkout` は **git 管理外の副作用(state ファイル等)を戻しません**。「捨てて打ち直す」で state だけ新しいまま残ります。
- HTML など配信物を更新したら **commit & push までが 1 セット**。push しないと反映されません。
- **リモートの無いリポジトリは git 管理下でも同期されません。**「向こうで動かない」だけでなく「向こうに存在しない」も疑う。

## 5. 検証の作法
- **「完了」「確定」「対策済」は実物を見るまで信じない。** 台帳が完了でも資料に残っていることがあります。
- **件数の一致はカバレッジの証拠になりません**(相殺で成立します)。突合はファイル名でなく中身で。
- **要約に無いことは「無い」ではありません。** 否定の主張をするときは原本を開いてから。
- **版番号の大小で新しさを判断しない。** V1.8 が V2.0 より新しい実例があります。mtime と中身で見る。
- 抽出器は**成功を名乗ったまま壊れます**。「読めた」と「正しい」を同じラベルにしない。

## 6. モデルの使い分け(Opus = 考える / Sonnet = 探す・読む)

**2026-10-09 ルール化。** Claude Code には「作業の種類でメインのモデルを自動で切り替える」機能は**ありません**(`opusplan` はプランモードかどうかで切り替えるだけ)。そこで **メイン = Opus のまま、単純作業を Sonnet のサブエージェントへ渡す**ことで実現します。

| 作業 | モデル | 呼び方 |
|---|---|---|
| ファイル・コード・Web の検索、読み出し、一覧化、件数数え、転記・抽出 | **Sonnet** | `Explore`(`~/.claude/agents/Explore.md` で Sonnet に固定済み)。Explore で足りない単純作業は `Agent` に `model: "sonnet"` を付ける |
| 設計・考察・製作・レビュー・指摘の再確認 | **Opus** | メインで行うか、`general-purpose`(メインのモデルを継承)。§1 のフレッシュなエージェントもこちら |
| ユーザーとの対話・合意形成・グリル | **Opus** | メインのみ(委譲しない) |

- **単一の事実の参照**(ファイル 1 つ開く、値を 1 つ見る)は委譲せずメインでやる。委譲のほうが遅い。
- Sonnet の結果は §1「受け取る側の責任」どおり、**Opus 側で検算してから**使う。
- `CLAUDE_CODE_SUBAGENT_MODEL` は**設定しない**。general-purpose まで Sonnet になり、§1 の考察エージェントが Opus でなくなる。
- 単純作業にも **Haiku は使わない**。2026-10-05 の調査で、重複の見落とし・行ズレ・未確認の「削除して安全」が出た。
- 配置: `Explore.md` の正本は `setting/claude/agents/`。`./install.sh --global` で `~/.claude/agents/` に入る。
